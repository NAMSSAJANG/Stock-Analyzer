# v6_A_0.3 업로드 안내

1. `analyzerbykijungnamv6_A_0.3.zip`을 압축 해제합니다. ZIP 최상위에 `app.py`가 바로 있습니다.
2. Streamlit 앱이 연결된 **기존 GitHub 저장소·브랜치의 app.py 위치**에 압축을 푼 전체 파일을 함께 올립니다. ZIP 파일 자체를 올리거나 `app.py`만 교체하면 적용되지 않습니다. 새 버전 폴더를 한 단계 더 만들어 기존 app.py 옆에 두지 마세요.
3. `app.py`, `trade_core.py`, `trade_engine.py`, `trade_lab.py`, `execution_engine.py`, `execution_lab.py`, `calibration_cache.py`, `calibration_engine.py`, `requirements.txt`, `release_manifest.json`이 같은 폴더에 있는지 확인합니다. `.streamlit/config.toml`과 `.github/workflows/checks.yml`도 포함합니다.
4. Streamlit 설정에서 배포 브랜치와 실행 파일 경로가 방금 교체한 `app.py`를 가리키는지 확인합니다. 이 배포본의 검증 환경은 Python 3.12입니다.
5. 업로드가 반영된 후 앱 오른쪽 아래 **Manage app → 메뉴(⋮) → Reboot app**을 실행합니다. 재시작 중에는 잠시 앱 이용이 중단됩니다.
6. 화면 위의 버전이 **v6_A_0.3**인지 확인하고 **Trade Lab**을 엽니다. 과거 진입 검증을 실행하면 **다음 날 시가 · 손절·목표 체결 검증**을 사용할 수 있습니다.

GitHub 웹 업로드에서 점으로 시작하는 폴더가 빠지지 않았는지 저장소 파일 목록에서 확인하세요. 기존 `.data`의 History DB는 이 ZIP에 포함되어 있지 않습니다. 기존 기록이 필요하면 먼저 앱의 History JSON 내보내기로 보관하세요.

## 로컬 확인

```text
python -m pip install -r requirements.txt
python verify_release.py
python -m streamlit run app.py
```

`verify_release.py`는 파일 누락·다른 버전 파일·실제 계산 함수 가져오기를 확인합니다. Git의 줄바꿈 변환(CRLF/LF)은 정상으로 처리합니다. 의도적으로 소스를 수정한 개발자는 검토 후 `python verify_release.py --write-manifest`로 기준을 갱신할 수 있습니다.

오류가 계속되면 Manage app 로그에 있는 **ImportError의 전체 문장**과 현재 배포 커밋을 확인해야 합니다. 첨부 화면처럼 오류 본문이 가려진 정보만으로는 서버가 어느 파일을 가져왔는지 확정할 수 없습니다.

공식 문서: [배포 파일 배치](https://docs.streamlit.io/deploy/streamlit-community-cloud/deploy-your-app/file-organization), [앱 재시작](https://docs.streamlit.io/deploy/streamlit-community-cloud/manage-your-app/reboot-your-app).
