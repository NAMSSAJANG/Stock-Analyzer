## Trade Lab 사용 순서

1. 보유수량, 비용을 포함한 기존 평단, 현재가, 추가매수용 현금을 입력합니다.
2. 수수료·거래세·체결오차를 실제 사용할 가정으로 입력합니다. 기본값 0은 무료 거래라는 판단이 아닙니다.
3. **매매 계산**에서 계획한 주문을 순서대로 계산하고, 청산 후 단순보유 대비 차이를 봅니다.
4. **시나리오**에서 5가지 경로와 직접 입력한 경로를 비교합니다. 조건을 충족한 주문은 관측가격에서 한 번만 처리되며 미체결도 자동 재시도하지 않습니다.
5. **손실 한도·순손익비**에서 신규 물량의 예산과 비중 한도를 계산합니다. 이미 보유한 종목의 위험은 이 탭의 손실 한도에 합산하지 않습니다.
6. **분할매수·하락 점검**에서 예산 배분과 일부 단계만 체결된 상태를 확인한 뒤, 추가 하락에 따른 자산 변화를 봅니다.

분할매수 예: 현금 1,000, 현금 보존 20%, 매수가 100/80, 가중치 1:1, 비용 0이면 예산은 각각 400입니다. 4주와 5주를 사며 현금 200이 남습니다. 정수 수량 때문에 남은 예산은 다음 단계에 자동 재배분하지 않습니다.

## 계산 기준

- 매수 실질 단가 = 입력 가격 × (1 + 체결오차율) × (1 + 매수 수수료율).
- 매도 실질 단가 = 입력 가격 × (1 − 체결오차율) × (1 − 매도 수수료율 − 매도세율).
- 청산가정 총자산 = 현금 + 보유수량 × 매도 실질 단가.
- 기간수익률의 분모는 시작 시가평가 총자산입니다. 청산가정 기간수익률은 시작부터 발생할 수 있는 매도비용도 드러냅니다.
- 청산가정 최대낙폭은 시작 시점의 청산가정 자산을 첫 고점으로 두고 각 관측점에서 계산합니다. 기간수익률과 최대낙폭의 기준 차이에 주의하세요.
- 누적 매매비용은 이번 실험에서 실제 처리된 주문의 비용 합계입니다. 기존 보유분의 과거 매수비용은 평단에 이미 들어 있다고 가정하며, 남은 주식의 미래 매도비용은 청산가정 값에만 반영합니다.
- 매수 수량 = 손실 한도 기준 수량, 현금 기준 수량, 신규 투입 비중 기준 수량 중 최솟값. 각 수량은 소수점 아래를 버립니다.
- 손익분기 승률 = 주당 손실 ÷ (주당 손실 + 주당 목표 순이익). 목표 순이익이 0 이하이면 달성 가능한 손익분기 승률을 표시하지 않습니다.
- 가정 기대손익 = 입력 도달 비율 × 목표 순이익 − 나머지 비율 × 손절 손실. 목표·손절의 두 가지 전량 청산 결과만 고려합니다.

손실 허용액과 손절 거리로 포지션 크기를 구하는 기본 개념은 [CME의 포지션 크기 설명](https://www.cmegroup.com/education/courses/trade-and-risk-management/proper-position-size)을 참고했습니다. 여기에 비용·현금·투입 비중 제한을 함께 적용했습니다.

과거 상승 비율에는 [NIST의 Wilson 구간 산식](https://www.itl.nist.gov/div898/handbook/prc/section2/prc241.htm)을 사용했습니다. 이 참고구간은 독립 표본을 가정합니다. 같은 종목·국면의 상관관계를 해결하는 방법은 아니며, 미래 상승 확률을 보장하는 구간도 아닙니다. 시장 초과수익은 해당 20D 표본과 같은 양 끝 날짜의 시장 가격을 사용하고, 없는 가격은 채우지 않습니다. 시장 비교 가능 표본 수를 별도로 표시합니다.

## 다음 업데이트 우선순위

### 1. 실제 체결 조건을 반영하는 과거 백테스트 — 가장 높은 우선순위

현재 과거 진입 검증은 신호일 종가 이후의 수익률 통계이고, Trade Lab은 사용자가 가정한 가격 경로입니다. 다음 버전에는 신호를 확인한 뒤 다음 거래일 시가에 진입하는 규칙, 일중 손절·목표가, 거래비용, 갭, 부분 체결을 추가하는 것이 좋습니다. 같은 봉에서 목표·손절이 모두 닿으면 보수적으로 손절을 먼저 처리하거나 더 세밀한 시세가 있을 때만 순서를 판정해야 합니다.

수익률·승률만 최적화하면 특정 기간에 맞춘 규칙이 될 수 있습니다. 규칙을 고르는 구간과 성과를 확인하는 구간을 시간 순서로 나누고, 검증 구간을 이동하는 방식의 평가가 필요합니다. 연 수익률·Sharpe·Sortino·회복기간은 이런 실제 거래일 경로를 확보한 뒤 추가하는 편이 타당합니다. 현재의 5~6개 가정 관측점에는 이를 붙이지 않았습니다.

### 2. 과거 시점별 시장·실적 환경 복원 — 높은 우선순위

`calibration_engine.py`는 과거 시장 점수를 중립 50으로 고정하고 실적 일정을 사용하지 않습니다. 실제 당시의 지수·변동성·섹터·실적 발표 일정이 확보되면 현재 분석과 더 가까운 조건으로 검증할 수 있습니다. 당시 공개되지 않은 재무정보를 과거 계산에 넣지 않도록 공개일도 관리해야 합니다. 한국·미국 시장의 마감 시각 차이도 반영해야 합니다.

### 3. 데이터 품질과 갱신 상태 표시 — 높은 우선순위

가격·거래량의 결측, 중복 날짜, 0/음수 값, 조회 실패, 데이터 기준일을 공통 검사하고 화면에 표시하는 계층이 필요합니다. 현재 일부 조회와 검증 루프는 예외를 건너뛰므로, 실패한 날짜·종목 수를 별도로 알리면 판단 근거가 더 명확해집니다. `risk_engine.py`의 한국 유동성 환산은 고정 근사 환율 1,350을 사용하므로 날짜별 환율 또는 한국 시장 전용 거래대금 기준도 검토할 수 있습니다.

### 4. 계좌 전체 위험과 Trade Lab 저장 — 중간 우선순위

현재 계산은 한 종목 또는 신규 진입 물량 중심입니다. 여러 종목의 합산 손실 한도, 업종 편중, 상관관계, 환율 영향을 함께 보는 계좌 화면이 다음 확장으로 적합합니다. Trade Lab 입력 계획을 이름별로 저장하고 불러오는 기능도 유용합니다. 이번 버전의 결과 유지는 브라우저 세션 안에서만 동작하며 영구 계획 저장은 CSV입니다.

### 5. 옵션 신뢰도·코드 구조·실행환경 정리 — 중간 우선순위

옵션 계산에는 거래량·미결제약정과 함께 매수/매도 호가 차이, 시세 시각, 만기별 자료 범위 등으로 신뢰도를 구분하는 확장을 권합니다. 미결제약정만으로 보유자의 매수·매도 방향을 확정할 수는 없습니다.

`app.py`가 3천 줄 이상이므로 화면을 모듈로 나누면 수정과 회귀 검증이 쉬워집니다. 검증 중 Streamlit의 `use_container_width` 사용 중단 예고도 확인했습니다. 다음 환경 정리에서는 지원 버전을 정한 뒤 `width` 방식으로 전환하고, 의존성 버전 고정 및 자동 회귀 검증을 함께 적용하는 것이 좋습니다. 이번에는 기존 requirements 범위를 유지했습니다.

## 검증과 범위

- 수치 자동 검증 33개 통과: 원가·현금 보존, 반복 250회 매매, 전량 매도, 비용 누계, 현금 보관, 미체결, 손실 한도, 분할 예산, 기간 수익률, Wilson 구간, 시장 데이터 누락 등.
- 기존 오프라인 분석 엔진 종합 검증 통과.
- Trade Lab 입력·버튼·결과 유지·오래된 결과 숨김·잘못된 경로·빈 보유·현금 0·메뉴 연결 검증 통과.
- 일반 분석 수량 계산기와 과거 검증 보강 화면의 오프라인 검증 통과.
- 로컬 브라우저에서 신규 위험 계산 탭과 분할매수 표·그래프 배치 확인.
- Python 3.12.14, pandas 2.3.3, numpy 2.5.2, Streamlit 1.63.0, yfinance 0.2.66인 기존 로컬 테스트 환경 사용.

실시간 시세·옵션·외부 검색의 전체 서비스 가용성이나 실거래 성과를 검증한 것은 아닙니다. 거래세율은 자동 적용하지 않으며 사용자가 입력한 비율만 사용합니다. 자동 환전, 배당, 주식분할, 이자, 양도소득세는 Trade Lab 계산에 포함되지 않습니다.

업데이트 ZIP에는 실행 코드, 검증 코드, 설정, 설명서가 포함됩니다. 기존 History 데이터, 캐시, 로그, 과거 앱 백업 사본은 배포본에서 제외했으며 원래 작업 폴더의 해당 파일들은 삭제하지 않았습니다.
